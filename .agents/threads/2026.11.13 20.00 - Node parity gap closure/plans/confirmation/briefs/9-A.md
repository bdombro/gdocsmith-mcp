### Implementation recipe
1. **Exports at top level, above the guard. No I/O when imported.**
   - `EXPECTED_CASE_IDS`: the ten IDs.
   - `EXPECTED_VARIANTS`: `[{ caseId: "V009-image-upload-lifecycle", variant: "known-upload-error" }]`.
   - `EXPECTED_CONTROLS`: the literal 70-entry list `{side, caseId, variant|null, name, requiredAssertion, type}` from the table above.
   - `assertFreshDestinations(paths, lstat = lstatSync)`:
     - Throws if any path's `lstat` succeeds, which covers files, directories and dangling symlinks.
     - Treats ENOENT as fresh.
     - Rethrows any other error.
   - `qualify(report)`, specified in step 4.
2. **Main guard.**
   - `isMain` = `process.argv[1]` exists and its `realpathSync` equals `fileURLToPath(import.meta.url)`.
   - Wrap everything currently at module top level in `if (isMain) { … }`: umask, argv, `ownedPath`, imports of the original parser, execution, and writes. Keep the existing logic unchanged except for the deltas below; re-indenting is acceptable.
3. **Freshness.**
   - Right after argv validation, before any `ownedPath` call or `mkdir`, call `assertFreshDestinations` on the resolved `--owned-run-root`, `--results` and the derived `-raw-diffs.json`. Keep the project-relative and `..` checks first so error messages stay correct.
   - Then run the existing `ownedPath`, ancestor and privacy checks. Create the run-root leaf without `recursive` so EEXIST stays fatal.
   - Write both reports with `{ mode: 0o600, flag: "wx" }`.
4. **`qualify(report)` returns `{ pass, reasons[] }` and never throws.** Wrap it in try/catch; any exception becomes reason `malformed report`. Fail if any of these holds:
   1. `schema` isn't `engine-parity-results-v1`.
   2. `cases` IDs don't exactly match `EXPECTED_CASE_IDS`: missing, duplicate or extra.
   3. `variants` don't exactly match `EXPECTED_VARIANTS`.
   4. Any case or variant `node`/`cpp` isn't `execution: "completed"` with an observation and a non-empty `assertions` array, or any assertion has `pass !== true`.
   5. Any `differential` isn't an array or has length greater than 0. Raw differences stay RED.
   6. The control multiset keyed by `side|caseId|variant|name|requiredAssertion|type` isn't exactly `EXPECTED_CONTROLS`. This catches missing, extra, duplicate and empty sets.
   7. Any control has `baselineWasPassing !== true`, `rejectedBy` without `requiredAssertion`, or `detected !== true`.
   8. Any backend control has `reached !== true` or `run.execution !== "completed"`.
   9. Any run, including `controls[].run`, has a cleanup status other than `"removed"`.
   10. `summary.ownedRunDirectoriesRemaining !== 0` (exact integer).
   11. `frozenInputs !== true` or `compiledInputsCurrent !== true`.
   12. Any `normalization.createdIdBijections[].valid !== true`.

   In the main block:
   - Store the result in `report.qualification` before writing the results file, and print `{summary, qualification}` to stdout.
   - Set `process.exitCode = report.qualification.pass ? 0 : 1`, replacing the old predicate.
   - Leave infrastructure exceptions uncaught so they stay nonzero.
5. **Cleanup in `execute`.**
   - Capture the child outcome in the try block. Keep `exitStatus` and `signal` on every run, completed or failed.
   - Then run cleanup in its own try/catch and attach `cleanup: { status: "removed" | "failed", reason }`:
     - If the marker is unreadable or changed, set `failed` and do not call `rmSync`. Keep the directory.
     - If `rmSync` throws or the directory still exists, set `failed`.
   - Never retry, and never delete outside the run directory.
   - An exception thrown inside the try block still propagates (nonzero exit); cleanup must not swallow it.
6. **Identity.** Add `"justfile"` to the target `fingerprint` extras. Keep the before/after equality, executable, runtime, dependency and build receipts, and the mtime staleness gate. Don't describe mtime as provenance.
7. **Tests:** `tests/parity/run-engine-differential.test.mjs` using `node:test` and `node:assert/strict`. Import only the exports.
   - Build one complete valid synthetic report from `EXPECTED_*`, with zero differences, `removed` cleanup, remainder 0, fresh inputs and valid bijections. It must pass.
   - One focused failing case per condition:
     - missing case; extra or duplicate case; missing variant
     - empty controls; one named control removed; one unexpected control added
     - `reached: false`; `baselineWasPassing: false`; `requiredAssertion` missing from `rejectedBy`
     - remainder 1; a recorded cleanup failure (including on a backend `run`)
     - `controls` missing; `differential: null`; missing side observation; launch failure; assertion failure
     - `frozenInputs: false`; `compiledInputsCurrent: false`
     - one raw difference while every assertion passes
     - invalid bijection
   - Each failing case asserts `pass === false` and that a reason is present.
   - `assertFreshDestinations` with a fake `lstat`: rejects an existing results path, raw-diff path, run root, or symlink stat result; accepts all ENOENT; rethrows a non-ENOENT error.
   - Importing the module performs no run and no writes. Running the file proves this.
8. **Recipe.** Place it after `test-mcp`, grouped with the verification recipes; record this reason (deviation from alphabetical order) in Notes. Single command, no shebang, no dependencies:

   ```just
   parity run_id node:
       "$2" tests/parity/run-engine-differential.mjs \
           --original-root ../gdocsmith-node \
           --target-adapter build/cmake/ParityChecks/gdocsmith_parity_adapter \
           --vectors '.agents/threads/2026.11.13 20.00 - Node parity gap closure/tasks/parity-evidence/proposed-vectors.json' \
           --case-ids V001-noop,V002-body-and-title,V003-stale,V004-landed-lost-response-replay,V005-font-default,V006-font-nondefault,V007-cell-style-edit,V008-reject-hidden-insertion,V009-image-upload-lifecycle,V010-cross-doc-image-copy \
           --owned-run-root ".agents/threads/2026.11.13 20.00 - Node parity gap closure/tasks/parity-evidence/$1/runs" \
           --results ".agents/threads/2026.11.13 20.00 - Node parity gap closure/tasks/parity-evidence/$1/differential-results.json"
   ```

   The driver's freshness and `ownedPath` checks reject reused or unsafe run IDs. Add no extra validation logic in the recipe.
9. **Docs.**
   - One AGENTS.md Commands row: offline Node-vs-C++ engine parity with a prebuilt ParityChecks adapter, a fresh run ID and an explicit Node; raw differences exit 1. Command: `just parity <run_id> <node>`.
   - One README note next to the qualification text, making the same points with no fresh-run claim.
   - Preserve the unrelated dirty hunks.
