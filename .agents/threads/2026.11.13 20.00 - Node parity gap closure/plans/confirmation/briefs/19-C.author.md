## Brief

### Why this task exists
`19-DC` (decision on `Q-L3` and `render.hpp:126`) needs a concrete implementation brief for aligning C++ frontmatter `namedStyleSets` / `cellStyles` serialization and import-time declaration handling with `../gdocsmith-node`, while preserving the already-decided `:style[]{}` (`render.hpp:126`) boundary from `11-D1` (`plans/confirmation/decisions/export-lens-repairs.md`).

### Observed current state vs target state
1. **`render.hpp:126` (`:style[]{}`):**
   - **Observed:** `src/lens/render.hpp:126` emits `:style[]{}` for empty `NORMAL_TEXT` paragraphs. `src/lens/put.hpp:614-615` (`tablePut`), `src/lens/project.hpp:384-393` (`inlineCell`), and `src/lens/put.hpp:760-762` (`containerPut`) rely on empty paragraphs projecting to a visible `:style[]{}` block (e.g., `tablePut` calls `if (projected.blocks.empty()) refuse();`).
   - **Target:** **No code change.** Keep `:style[]{}` as a documented C++ vs Node lens difference per `11-D1` (`plans/confirmation/decisions/export-lens-repairs.md`).
2. **`namedStyleSets` key naming & deduplication:**
   - **Observed:** `src/engine/export.hpp:385-389` generates sequential `"ns" + std::to_string(docFile.tabs.size() + 1)` keys (`"ns1"`, `"ns2"`, ...) without deduplicating identical `namedStyleSets` across tabs.
   - **Target:** Match `../gdocsmith-node/src/core/lens/document.ts:435-441` — reuse an existing key if an identical `diffNamedStyles` object is already in `docFile.frontmatter.namedStyleSets`, otherwise assign `std::to_string(docFile.frontmatter.namedStyleSets.size() + 1)` (`"1"`, `"2"`, ...).
3. **`cellStyles` omission when empty:**
   - **Observed:** `src/lens/document.hpp:535` iterates `file.frontmatter.cellStyles` (which is a `std::map`, so an empty map already writes nothing to `fm["cellStyles"]`).
   - **Target:** Verify `cellStyles` is omitted from frontmatter YAML when empty (already satisfied by `for (const auto& [name, value] : file.frontmatter.cellStyles)` in `src/lens/document.hpp:535`).
4. **Named-style / cell-style declaration edits on import (`Q-L3`):**
   - **Observed:**
     - `src/engine/import.hpp` already reads `file.frontmatter.namedStyleSets[*set]` when applying `namedStyleSet` to tabs, and `readonlyValidate` (`src/engine/import.hpp:712-728`) only locks `apiUser`, `guards`, `styleBaseline`, and `variables` (not `namedStyleSets` or `cellStyles`).
     - `AGENTS.md` §Safety & App Conventions #6 states: *"Supported body-rich edits, tab operations and Drive comment actions do not imply atom mutation, merged/resized-table editing, non-body editing, style-declaration changes or protected review edits. Preserve unchanged metadata and refuse unsupported changes before sends."*
   - **Target (contingent on `19-DC` decision on `Q-L3`):** Either (a) keep `Q-L3` as an accepted capability narrowing (documenting it alongside `:style[]{}`), or (b) if `19-DC` selects Node parity, ensure `namedStyleSets` / `cellStyles` declaration edits in `export.md` frontmatter are applied on `import` without `readonlyValidate` refusal.

### Non-goals
- Do **not** modify `src/lens/render.hpp:126`, `src/lens/project.hpp`, or `src/lens/put.hpp` (`tablePut` / `containerPut`) to suppress `:style[]{}`.
- Do **not** port Node's `owned` / `leadingOwned` invisible-paragraph lifecycle.
- Do **not** relax `readonlyValidate` for `apiUser`, `guards`, `styleBaseline`, or `variables`.

1. **Verify `render.hpp:126` (`:style[]{}`) remains untouched:**
   - Confirm `src/lens/render.hpp:126` still emits `:style[]{}` and `tests/lens/test_render.hpp:43` / `tests/lens/test_document.hpp:78` remain green.
2. **Update `namedStyleSets` key generation & deduplication in `src/engine/export.hpp:385-389`:**
