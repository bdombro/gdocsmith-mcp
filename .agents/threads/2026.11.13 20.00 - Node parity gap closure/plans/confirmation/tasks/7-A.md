  - The classifier is `suggestionRuleApply(const TabModel& base, TabModel& candidate)` in suggestion_rule.hpp. It throws `suggestionConflict` naming the ID on any refusal.

  - (a) The target's first failure is the `suggestionConflict` throw in `paragraphPut`, not a parse or projection failure.

  - (c) The backend (FakeGoogle/reconcile) realizes the carried marks without changes.

### Implementation recipe
1. **Characterize (failing first).**
   - In tests/engine/test_import.hpp, add a helper next to `seedSuggestion` that seeds multi-run paragraphs. It must cover a deletion+insertion replacement pair with a shared ID, and a `suggestedTextStyleChanges` span with an ID.
   - Port the three import.test.ts l.352–408 tests as `TEST_CASE("import parity - review carry ...")`. Keep the source line comment, as at l.717.
   - Assert the same things the original does:
     - status and verification `match`
     - exact ordered runs of text plus mark IDs
     - unchanged hidden insertion text and ID
     - for the cross-edge test, the error names the pending ID and `batches`/`sentRequests` are unchanged, then `isReject` yields plain text
   - Run and record the actual failing stage and message for each case before any repair.
2. **Lens alignment (src/lens/put.hpp `paragraphPut`).**
   - Keep a mapping from visible written symbols to model symbol indices, so hidden insertion symbols keep their original gap and are never diffed away. A replacement ending next to a hidden insertion must not consume it.
   - Gate the l.310-ish pending-mark throw, and the size-mismatch refusal only if step 1 shows it fires, behind the new opt-in. The default path stays unchanged.
   - New characters take no marks in the lens. Marks are assigned only by the classifier.
3. **Classifier (src/engine/suggestion_rule.hpp).**
   - Port `suggestionRuleApply`/`paragraphRuleApply`:
     - Diff the base paragraph against the candidate paragraph by symbol.
     - Group replacement hunks separated only by kept whitespace.
     - Carry identical non-empty marks across eligible spans of at least two characters.
     - Pure insertions strictly inside a span take `joinMarks`-equivalent marks, via a local port.
     - Refuse when a suggestion ID present in the base disappears without reject, or when a replacement crosses a hidden insertion or has mixed marks or edges.
   - One-character and fully deleted spans are not blanket carry cases. Follow the original exactly.
4. **Wire (src/engine/session.hpp `writeSegment`).**
   - Keep a copy of the post-reject candidate as `base` before `markdownPut`.
   - Pass the opt-in.
   - Call `suggestionRuleApply(base, candidate)` before `tab = std::move(candidate)`. A throw leaves `tab` untouched and nothing is sent.
5. **Controls and boundaries.**
   - Run each control temporarily, then revert it: drop the deletion ID, mutate the hidden insertion text or ID, drop the style ID, allow the crossing replacement without reject. Each must fail its ordered-state or refusal assertion. Record the results in Notes. Controls are not committed as permanent mutations.
   - Add cheap cases in tests/lens/test_put.hpp or test_import.hpp:
     - insertion exactly at an edge
     - insertion inside a span
     - one-character replacement
     - whole-span deletion
     - whitespace-separated cross-edge replacement
     - standalone `markdownPut` still throws `suggestionConflict` on a marked edit
6. Update docs/suggestions.md only if the documented capability changes.
