### Decisions and alternatives
- Established: D4-R3 (accepted, lead), with the D5 graph and ownership (src/api.hpp and tests/api/test_api.hpp only).
- Proposed:
  - The checked helper wraps raw `google_api_fetch` and throws `GoogleApiError` when status ≥400.
  - In `getDocument`, an unsuccessful final response throws `std::runtime_error(gws_error_format(body,cleanId))` before parsing. This keeps the current public type, which is not `GoogleApiError`.
- Alternatives (rejected in D4-R3): a 404-only test fix; declaring the discrepancy internal; per-method duplicate checks.
- Assumptions: exhausted-transient behavior in the original matches its returned-final-response code path (cited; not executed). Original test execution is unverified.

### Implementation recipe
1. Characterize first, with tests in tests/api/test_api.hpp. Count resource calls only and exclude the oauth token URL, following the existing test pattern.
   - Raw `fetch_with_retry` on 404 returns status, body and headers in one call.
   - Public `DocsClient::getDocument` on 404 with error JSON rejects with the formatted message and never returns the JSON.
2. In src/api.hpp:
   - Rename the throwing behavior into a checked helper, for example `google_api_fetch_checked`. Its body is raw `google_api_fetch` plus the existing ≥400 throw.
   - Make `google_api_fetch` return without throwing.
   - Switch every caller listed above to the checked helper. This includes the discarded PATCH and DELETE calls and the image readback, which must keep the ImagesUploadError wrapping at :1656.
   - The checked helper must never call `fetch_with_retry`.
3. In `fetch_with_retry`, remove the ≥400 throw and return `res` after the retry decision. On the final attempt, a 429/5xx response is returned. Transport exceptions keep their current retry handling.
4. In `getDocument`, if status ≥400, throw `std::runtime_error(gws_error_format(res.body, cleanId))`, then parse.
5. Tests:
   - Change the permanent-400 case to assert a returned 400 with one call on the raw path.
   - Add a checked-boundary 400 case that asserts a throw with one call. This relocates the existing assertion; it does not retire it.
   - Add: exhausted 429/503 returns the final response after `retries` attempts; 501 is returned after one call; a representative checked Docs write (batchUpdate) error throws `GoogleApiError` with its status after one call (no replay); a Drive DELETE error throws.
   - Keep the existing transient-success and write no-retry tests.

- Behavior contract: raw results always carry status, body and headers. Checked and public errors keep today's types, status field and `gws_error_format` text, which app.hpp:490 depends on.
- Failure/lifecycle contract: writes are never retried or replayed. The single 401 refresh is unchanged. A partial upload still produces ImagesUploadError.
- Local decision boundary: helper name, test names and fixtures.
- Escalate to coord-v2 or lead: any change to app.hpp, to exception types or messages, to retry policy, or to the quirk decision below.
