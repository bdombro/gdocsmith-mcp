# Node behavioral parity gap closure

## Goal

Close the remaining Node-to-C++ behavior gaps and preserve meaningful source test obligations. A green bounded safe-editing subset, equal filenames or test totals do not establish replacement parity.

## Structure

Analysis root: this C++ repository. `../gdocsmith-node` is the read-only behavioral reference; existing dirty work and the previous implementation thread are preserved. The accepted [workspace brief](../../workspace.md) supplies shared-file ownership and existing-cache commands.

## Findings and recommendations

- Node supports table geometry/layout, section/page settings and style declarations that the C++ public path currently refuses.
- Headers, footers and footnotes are read-only in C++; Node edits them.
- General atom/chip/image/link mutations and suggestion rejection require further porting, not just read-only export context.
- Source stale-input outcomes use `refused`, not target `failed`; new-document rollback needs truthful `reverted`/cleanup behavior. Engine lane owns these corrections.
- Native file-envelope versions differ; initial differential scenarios may export each native envelope, but raw Node-file interchange remains a separate unresolved obligation assigned to the lens lane.
- C++ conformance testing silently skips unreadable/malformed fixtures. A copied, corrupted `B1.json` still passed; fail-closed regression sensitivity is required.
- Transfer meaningful assertions and parameter distinctions with explicit dispositions. Run common vectors against actual original and replacement code; do not treat the target-free portable foundation as application parity.
- Continue incrementally from the existing typed, guarded transaction core, not a 1:1 filename rewrite.

## Patterns & rules

- Parent owns decisions, launches, permissions, acceptance and this map alone. Source workers own disjoint paths; coordinator alone owns the inbox, scribe owns thread state/workspace/index and unassigned scaffolds.
- Preserve revision locking, reverse-index requests, atomic putback, authoritative readback, honest partial/unknown results, private artifacts and local edits. No blind retries or weakened checks.
- Node production/tests/fixtures are read-only. Source behavior can be retired only with evidence and authority, not because C++ refuses it.
- Sanitize every artifact before writing: no secrets, sensitive personal data, confidential source bodies or raw transcripts.
- No commits/pushes, Google/account calls, auth changes, persistent services or dependency installations are authorized. Previous live permissions are consumed.
- Use harness defaults; actual worker model/effort and worker-chat links are unavailable in launch results. Never infer them or fabricate links from agent IDs.
- Maximum four executing turns. All helpers, repairs, reviews and follow-ups share the overall budget; use completion notifications, not polling or keepalives.
- Worker checks mean ready for review, not accepted. Independent examination and fresh final source-bound validation remain required.
- The map is the status surface; reserve chat for required messages, questions, direct answers and final delivery.
